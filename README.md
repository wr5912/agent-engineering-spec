# 智能体研发规范

一套从需求、最小实验、Harness 开发、自测、交付评估到发布与持续回归的可执行规范。

> 从真实任务出发，用最小实验取得证据；以冻结基线上的正式自测和交付评估决定能否发布。
> 
> TIP: 适用于DeepSeek-Harness、Claude、Codex、AgentScope等成熟Agent。

## 快速开始

1. 先阅读[《00｜智能体研发总纲》](./00_总纲.md)，统一术语、角色、状态和强制门禁。
2. 按[《01｜研发流程与最小实验》](./01_研发流程与最小实验.md)推进工作和角色交接。
3. 开发成员提交前使用[《09｜智能体研发检查清单》](./09_研发检查清单.md)自查。
4. 交付负责人依据[《06｜交付评估与发布规范》](./06_交付评估与发布规范.md)复核整体交付，发布执行人只发布评估通过的同一候选基线。

完整主线：

```text
需求确认 → 最小实验 → Harness 开发与针对性检查 → 冻结候选基线
→ 全量正式自测 → 提交交付物 → 分级复核 → 发布同一基线 → 反馈进入回归
```

探索样本只能用于判断方向，不能代替正式自测；正式输入集禁止用重复改写、无效变体或低质量输入凑数。

## 使用原则

- 需求和成功标准不清楚时，不进入复杂设计。
- 能用更简单 Harness 验证的，不提前引入复杂编排或平台。
- 针对性检查只服务开发反馈，不能形成正式交付结论。
- 交付评估同时检查需求完成度、能力、安全、材料和可复现性，不只看一次演示效果。
- 任何冻结项发生变化都要重新形成候选基线并完成相应自测和评估。
- 生产失败和高价值反馈必须沉淀为回归 Case，成为下一轮改进的事实输入。
