# 智能体研发规范

一套按任务类型组织需求定义、探索验证、智能体运行支撑配置开发、评估和交付的可执行规范。本页提供使用入口，具体规则、字段和判定以各章节正文为准。

本规范适用于基于 DeepSeek Harness、Claude Code、Codex、AgentScope 等框架或工具开展的智能体研发，也适用于其他具有模型调用、工具调用、运行支撑配置或自主执行能力的智能体；具体要求不依赖任一特定框架。

项目从任务来源和最小任务契约开始。先判断当前属于研究探索、已知缺陷修复、外部资产复用、迁移，还是正式生产交付，再采用相应记录深度；正式交付的需求、验收和发布字段以[《02｜需求定义与场景输入规范》](./02_需求定义与场景输入规范.md)为准。

## 快速开始

1. 阅读[《00｜智能体研发总纲》](./00_总纲.md)，先选任务路径并确认共同最小要求、安全边界和完成判定。
2. 按[《01｜研发流程与按需探索验证》](./01_研发流程与按需探索验证.md)开展任务；需求、场景和验收字段按需要参考[《02｜需求定义与场景输入规范》](./02_需求定义与场景输入规范.md)。
3. 涉及外部 Skill、工具、MCP 或数据资产时，先读[《10｜外部资产复用与集成》](./10_外部资产复用与集成.md)，再按[《03｜Harness 开发与变更规范》](./03_Harness开发与变更规范.md)记录实际适配。
4. 非生产任务按上述章节的最小要求收尾；正式生产交付再使用[《09｜智能体研发交付检查清单》](./09_研发检查清单.md)、[《06｜交付评估与发布规范》](./06_交付评估与发布规范.md)和六件套模板。

共同最小路径：

```text
任务与预期结果
→ 输入、前置条件与安全边界
→ 必要时探索 / 复现 / 适配 → 实现与针对性检查
→ 记录观察、限制和决策
```

正式生产交付在此基础上增加：

```text
确认正式需求与验收 → 冻结候选基线 → 正式评估与复核
→ 同一基线发布 → 线上验证、运行观察与回归
```

## 阅读约定

正文优先使用中文。代码字段、命令、文件名或行业通用缩写确需保留英文时，首次出现应当说明中文含义和实际用途。

以下核心术语在[《00｜智能体研发总纲》](./00_总纲.md)中统一定义：

- **智能体运行支撑配置（Harness）**：驱动智能体行为的提示词、上下文、工具、技能、编排和运行配置；
- **候选基线（Baseline）**：正式自测前冻结的待测版本组合；
- **评估执行编号（`run_id`）**：标识一次写入结果事实源的独立执行；只有完整执行冻结的正式评估范围，才形成正式评估运行结论；
- **评估数据集（Eval Set）**：版本化的一组评估用例；
- **评估用例（Eval Case）**：可独立执行和判定的测试单元。
- **四类对象**：开发者运行配置、目标 Harness 资产、需求/测试数据/评估标准、运行状态与记录；不得把它们混成一个配置目录。
- **版本与执行**：参考/控制版本用于对照，被测版本用于本次验证，`run_id` 用于定位一次实际执行。
- **适配状态**：已安装、已加载、接口可调用、已适配当前任务、在目标行为上有效是不同结论。
